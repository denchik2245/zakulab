# Админка zakulab

Панель управления доступна по адресу `/admin`.

## Настройка на Netlify

Добавьте в **Project configuration → Environment variables**:

- `ADMIN_PASSWORD` — длинный уникальный пароль администратора;
- `ADMIN_SESSION_SECRET` — случайная строка длиной не менее 32 символов.

После добавления переменных выполните новый production deploy. Netlify Blobs создаётся автоматически при первом сохранении из админки; отдельная база данных и токены не нужны.

## Что можно редактировать

- менять все тексты главной страницы: первый экран, «Обо мне», портфолио, процесс, отзывы, услуги, быстрые задачи, контакты и подвал;
- загружать портрет, изображения галерей, проектов, этапов работы и блока отзывов;
- добавлять и редактировать проекты на главной странице;
- создавать подробные кейсы, хранить их в черновиках и публиковать;
- менять содержание, порядок, категорию, цвет и ссылки кейсов;
- одобрять, отклонять и редактировать отзывы.

Загрузчик принимает PNG, JPEG, WebP и GIF размером до 8 МБ. В Netlify файлы хранятся в отдельном Blob-хранилище `zakulab-media`; в локальной разработке — в `.data/media`. Если изображение уже размещено в другом месте, вместо загрузки можно указать его URL.

Новые отзывы из публичной формы получают статус `На проверке` и не показываются на сайте до одобрения.

В редакторе отзыва выберите статус «Опубликован» и нужные места размещения. Статус «Демонстрационный» всегда сопровождается видимой подписью на сайте. Форма требует отдельного согласия на обработку и публикацию; время и версия согласия сохраняются с отзывом. Для старых отзывов согласие нужно проверить самостоятельно.

Входящие отзывы хранятся отдельно от CMS в `zakulab-cms/review-queue/0..99`: максимум 100 необработанных отзывов, срок ожидания — 90 дней. После модерации запись сохраняется в `content-v1`, а слот очереди может использоваться повторно. Публичная форма допускает 3 запроса в час, вход — 10 попыток за 15 минут. Лимиты используют условные записи общего хранилища, действуют между инстансами и возвращают 429. Ключи лимитов распределены по 4096 хеш-группам: изредка разные адреса могут разделить лимит. За пределами Netlify используется общий лимит для всех клиентов, чтобы не доверять подставленному `X-Forwarded-For`.

Сохранение CMS проверяет версию документа. При конфликте показывается ошибка; сначала сохраните нужные правки отдельно, затем нажмите «Загрузить актуальную версию» и повторите изменения. Открытая админка не удаляет отзывы, поступившие во время редактирования.

Черновик кейса не подменяет внешнюю ссылку карточки. После публикации карточка открывает внутренний кейс; после отключения — внешнюю ссылку, если она задана. Без назначения карточка отображается без активной ссылки. Кейсы с `[УТОЧНИТЬ]` остаются черновиками до заполнения.

Внешние изображения загружаются непосредственно браузером. Для оптимизации и независимости от внешнего хоста используйте штатную загрузку файлов. Загружаемый файл проверяется по фактическому формату и ограничению количества пикселей.

Кнопка «Выйти» завершает текущую сессию. Смена `ADMIN_PASSWORD` или `ADMIN_SESSION_SECRET` отзывает все ранее выданные сессии.

## Локальная работа

Скопируйте `.env.example` в `.env.local`, задайте секреты и запустите `npm run dev`. Локальные изменения админки сохраняются в `.data/zakulab-content.json`, а загруженные файлы — в `.data/media`; эта папка исключена из Git.

Если локальные переменные не заданы, для разработки используется пароль `admin`. В production запасного пароля нет: без `ADMIN_PASSWORD` вход будет закрыт.

## Резервная копия

В Netlify откройте **Blobs → zakulab-cms → content-v1**. Объект можно скачать как JSON и использовать как резервную копию основного документа CMS. Загруженные изображения находятся в **Blobs → zakulab-media** и резервируются отдельно.

Вместе с `content-v1` резервируйте `review-queue/` — там находятся ещё не сохранённые администратором входящие отзывы. Для локальной резервной копии сохраняйте всю `.data`, включая `.data/review-queue`. При аварийной остановке во время записи может остаться файл `.lock`: удалять его можно только после остановки всех процессов сайта и сохранения резервной копии.

## Проверки перед публикацией

`npm run lint`, `npm test`, `npm run build`, `npm audit`. Регрессионные тесты работают с отдельными адаптерами и временным каталогом; реальная CMS не изменяется. Для проверки production GET запустите `npm run start -- --hostname 127.0.0.1 --port 3107`, затем `npm test -- http://127.0.0.1:3107`.
