# zakulab на PHP — Beget и обычный виртуальный хостинг

Сервер: PHP 8.2+ с JSON, mbstring, GD, fileinfo и PDO MySQL при использовании MySQL. Node.js нужен **только локально для сборки браузерных JS/CSS и подготовки изображений**. На Beget не нужны npm, Node.js, SSH, cron и фоновые процессы.

Публичные страницы формируются PHP с полным HTML, метаданными и canonical. После первого открытия они сохраняются в статические HTML-файлы. Apache отдаёт готовые страницы без запуска PHP. Сохранение контента очищает кэш. Сайт доступен поисковикам без JavaScript. React остаётся браузерным интерфейсом админки, фильтров, меню, модальных окон, слайдера и теста стилей.

## Подготовка

```sh
npm ci
npm run package:php
npm run test:php
```

Пакет для размещения появится в `build/beget/`, ZIP-архив — `build/zakulab-beget.zip` (команда `package:php` заново собирает пакет):

```text
site-directory/
  config.local.php       секреты, вне корня сайта
  config.example.php
  console.php            локальные служебные команды
  app/                   PHP-код, шаблоны, схема данных
  storage/               контент, заявки, отзывы, изображения
  public_html/           ТОЛЬКО эта папка — корень сайта
    index.php
    .htaccess
    assets/ fonts/ bundles/ optimized/
    page-cache/          только общедоступные HTML-страницы
```

Папки `app`, `storage` и `config.local.php` никогда не размещайте внутри публичного корня. Это позволяет защитить данные и конфигурацию независимо от настроек Apache. На Beget папки можно загрузить через файловый менеджер или FTP рядом с `public_html`. Если у сайта другая структура, измените путь к `app/src/bootstrap.php` в `index.php` и соответствующие пути в PHP-функциях; стандартная структура предпочтительна.

На HostiMan публичная папка сайта фиксирована как `www/zakulab.ru`. Разместите `app`, `storage` и `config.local.php` в `www/`, а содержимое `public_html` — в `www/zakulab.ru/`. В конфигурацию добавьте `'web_root' => __DIR__ . '/zakulab.ru'`, чтобы PHP сохранял кэш в правильную папку. Относительный путь к приложению в `index.php` при такой структуре остаётся прежним.

## Конфигурация

Скопируйте `config.example.php` в `config.local.php`, укажите `site_url` без завершающего слеша, например `https://zakulab.ru`.

Сгенерируйте секреты **локально**:

```sh
php build/beget/console.php secret
php build/beget/console.php password-hash
```

Первый результат вставьте в `session_secret`, второй — в `admin_password_hash`. Открытого пароля в конфигурации нет. Пустые поля закрывают вход в production; пароля `admin` не существует. Смена хеша пароля или секрета отзывает ранее выданные сессии.

Для MySQL создайте базу в панели Beget и заполните `driver => mysql`, `mysql_dsn`, `mysql_user`, `mysql_password`. Таблица `zakulab_entries` создаётся автоматически. Для одного небольшого сайта можно оставить `driver => file`: записи атомарны и защищены файловой блокировкой. Интерфейс и поведение одинаковы. Права на запись нужны только `storage` и `public_html/page-cache`.

PHP-загрузки: `upload_max_filesize` не менее 8M, `post_max_size` не менее 9M; приложение принимает изображения до 8 МБ и 5 мегапикселей, максимум 16000 пикселей по стороне. Админка уменьшает большие PNG/JPEG/WebP в браузере, сохраняя пропорции длинных скриншотов. GIF сохраняет анимацию, его необходимо уменьшать заранее. Превью создаются при загрузке, а не при каждом открытии страницы.

## Локальная проверка

```sh
npm run dev
```

Откроется PHP-сервер по адресу `http://127.0.0.1:8080`. Локальные данные хранятся в `php/storage`, вне генерируемой сборки: повторный `npm run build` не удаляет правки админки и включает их в новый пакет. Для входа задайте `ADMIN_PASSWORD_HASH` и `ADMIN_SESSION_SECRET` через окружение либо скопируйте пример в `php/config.local.php` и заполните секреты там. Скрипт запуска подставляет локальный адрес сайта. Секреты не коммитьте. Проверка `npm run test:php` сама генерирует временные секреты и использует отдельное хранилище — реальные данные не меняются.

## Данные и перенос с Netlify

При первом переходе сборка копирует нормализованный локальный контент из `.data` в приватный `storage/initial-content.json` и локальные изображения в `storage/media`. При последующих сборках сохранённые PHP-данные из `php/storage` имеют приоритет. Это данные **только для новой установки**: существующее рабочее хранилище при обновлении не заменяйте. Повторная сборка не забирает автоматически изменения с Netlify.

Перед переключением домена экспортируйте реальное production-наполнение:

1. Сохраните `content-v1` и все записи `review-queue/` из Netlify Blobs `zakulab-cms`.
2. Скачайте все файлы из `zakulab-media`, сохраняя исходные имена. Положите их в `storage/media`. Старые URL `/api/media/…` сохраняются.
3. Для совместимости старый JSON сначала можно поместить в локальную `.data/zakulab-content.json` и выполнить сборку: она использует существующую нормализацию старых форматов.
4. Для переноса очереди соберите JSON `{ "content": ..., "queue": [...] }`. PHP-экспорт также содержит `requests`. Импортируйте локально перед загрузкой нового сайта:

```sh
php build/beget/console.php import /absolute/path/export.json
php build/beget/console.php warm-cache
```

Если нет доступа к Netlify Blobs, войдите в действующую админку, откройте `/api/admin/content` и сохраните JSON. Он уже содержит входящие отзывы из очереди. Для перенесённых оригиналов можно локально создать WebP-превью: `node scripts/prepare-php-media.mjs php/storage/media`, затем собрать пакет. Оригиналы сохраняются; новые загрузки в PHP создают превью автоматически.

При использовании MySQL и отсутствии SSH экспорт можно сначала импортировать в файловый режим локально, загрузить подготовленную приватную папку `storage`, затем использовать файловый режим. Для переноса из файлового режима в MySQL выполните CLI-импорт на машине с доступом к вашей БД или импортируйте подготовленный SQL через phpMyAdmin. Не меняйте driver без переноса сохранённых записей.

Никогда не перезаписывайте рабочие `storage`, `config.local.php` и базу при обновлении файлов сайта. Старые HTML-файлы `page-cache` при обновлении удалите, чтобы посетители получили актуальные JS/CSS. На первом размещении загружайте кэш последним, после настройки адреса сайта.

## Формы и заявки

Отзывы приходят на модерацию в прежнюю админку. Очередь ограничена 100 отзывами и сроком 90 дней. Публичный API не отдаёт неопубликованные отзывы или черновики кейсов.

Заявки отправляются на `/api/requests`, форма находится на `/request`. Они сохраняются приватно и доступны в блоке «Заявки с сайта» под админкой. Вместимость — 100 заявок; при заполнении API явно сообщает об ошибке и не показывает ложный успех. Письма и внешние API не нужны. Уведомления по почте на бесплатном Beget не обещаются. Кнопки связи в мессенджерах остаются.

## Бэкапы и восстановление

В админке ссылка «Скачать резервную копию» скачивает приватный JSON с контентом, очередью отзывов и заявками. Файлы изображений сохраняйте отдельно из `storage/media`; конфигурацию — отдельно в безопасном месте. CLI-экспорт:

```sh
php build/beget/console.php export /absolute/path/backup.json
```

Перед CLI-импортом сохраняется копия предыдущего контента, очереди и заявок. Импорт — явная операция восстановления, он заменяет сохранённый контент. Данные нельзя редактировать одновременно с восстановлением.

## Публикация

Загрузите пакет на Beget, настройте конфигурацию, проверьте `/`, `/projects`, `/reviews`, `/style-check`, существующие кейсы, вход и сохранение в `/admin`, пробный отзыв и `/request`. Убедитесь, что `/storage/`, `/app/`, `/config.local.php` и `/page-cache/` не раскрывают данные. Проверьте HTTPS и настройки адреса сайта. Только затем меняйте A-запись `zakulab.ru`.

Технический адрес вида `логин.beget.tech` работает по HTTP и подходит для проверки публичных страниц. Пароли и приватные формы через него не отправляйте. Для действующего `zakulab.ru` сначала убедитесь, что выбранный аккаунт позволяет установить SSL: в проверенной панели FreeHosting пункт управления SSL отсутствовал. Не подменяйте рабочий HTTPS-сайт вариантом без HTTPS.

Лимит 10 CP проверяется по реальной статистике Beget. Статический кэш снижает нагрузку, но не гарантирует конкретное число посетителей. Если Beget принудительно убирает cookie после превышения лимита, авторизация в админке работать не сможет до снятия ограничения.

Исходная Next.js-версия оставлена для сравнения: `npm run legacy:dev`, `npm run legacy:build`. Она не входит в PHP-пакет.

`npm run test:apache` проверяет настоящий Apache/FastCGI и `.htaccess`, в том числе отдачу кэша при остановленном PHP. По умолчанию использует Apache macOS; для другой установки можно задать `APACHE_BINARY`, `APACHE_MODULE_PATH` и `PHP_CGI_BINARY`. Автоматические проверки используют файловое хранилище; адаптер MySQL требует отдельной проверки на выбранной базе перед включением.
